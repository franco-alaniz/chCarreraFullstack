Actividad: Pre-Entrega 2: Lógica de Programación y Control de Flujo

¡Felicidades por llegar al final del segundo módulo! Hasta ahora, has aprendido a declarar variables, interactuar con el usuario y, lo más importante, a tomar decisiones con el código y repetir tareas automáticamente.

Este entregable es un paso intermedio fundamental, ya que es la base lógica sobre la que construiremos aplicaciones más complejas. En esta etapa, nos aseguraremos de que dominas la "columna vertebral" de cualquier programa: la capacidad de controlar exactamente qué instrucciones se ejecutan y cuántas veces.

El objetivo

El propósito de esta pre-entrega es consolidar el uso de bucles (loops) y condicionales. Un programador no solo escribe código que funciona, sino código que sabe cuándo detenerse, cuándo saltar pasos innecesarios y cómo manejar diferentes escenarios lógicos.

¿Qué construirás?

Vas a desarrollar un Algoritmo de Interacción Lógica. Este script debe ser capaz de procesar una serie de entradas (datos) del usuario, evaluarlas mediante condiciones y repetir procesos hasta que se cumpla un stop específico.

Instrucciones del Checkpoint

1. Estructura de Decisión (Condicionales)

Debes usar if, else if y else para bifurcar el flujo. Por ejemplo: validar si un número es mayor que otro, si un string coincide con una clave, o si un usuario tiene permisos. Opcional: Puedes usar un switch si tienes múltiples opciones fijas (como un menú de selección).

2. Estructura de Repetición (Bucles)

Debes implementar al menos un bucle (for, while o do...while).

  • Usa for si conoces la cantidad de veces que quieres repetir algo (ej: mostrar los números del 1 al 10).
  • Usa while si la repetición depende de una condición que el usuario puede cambiar (ej: repetir hasta que el usuario escriba "ESC").
  • Usá do...while si querés que el bloque se ejecute al menos una vez antes de chequear la condición (ej: pedir un dato con prompt y repetir hasta que sea válido). Si no lo viste en la clase en vivo, repasalo en la unidad "Repetición con for, while y do...while" de este mismo módulo: está explicado con ejemplos, errores comunes y quiz.

Criterios de Aceptación

El repositorio debe:

  1. Funcionar sin errores: No debe haber errores de sintaxis al abrir el archivo.
  2. Combinar estructuras: Debe existir al menos un bucle que contenga un condicional dentro.
  3. Interactividad: El script debe interactuar con el usuario mediante prompt o console.log.
  4. Desarrollo con sentido: No deben ser herramientas sueltas, el script debe funcionar en un contexto de simulador.

Método de entrega: Se deberá enviar el link del repositorio de github en modo público.

Ejemplo de main.js (adaptalo a tu propio simulador — este es un control de acceso con reintentos):


// Simulador: control de acceso con reintentos
const CLAVE = "coder";
let intentos = 0;
let acceso = false;
// BUCLE: repite hasta 3 intentos o hasta acertar
while (intentos < 3 && !acceso) {
  const ingreso = prompt("Ingresá la clave:");
  // CONDICIONAL dentro del bucle
  if (ingreso === CLAVE) {
    acceso = true;
    console.log("✅ Acceso concedido");
  } else {
    intentos++;
    console.log(`❌ Clave incorrecta. Intentos restantes: ${3 - intentos}`);
  }
}
// Resultado final coherente al terminar el bucle
if (!acceso) {
  console.log("🔒 Cuenta bloqueada por demasiados intentos");
}

Fijate que hay un bucle (while) que contiene un condicional (if/else) — exactamente lo que pide el criterio "Combinar estructuras".

Instrucciones para la Pre-entrega

  1. Estructura de archivos: Crea una carpeta para tu proyecto con un archivo index.html y un archivo main.js en su correspondiente carpeta. Vincula el script en la etiqueta head del HTML con el atributo defer.
  2. Definición del Problema: Situate en una parte del simulador elegido a desarrollar que requiera repetición y decisiones (ej: un contador de puntos de un juego, un validador de stock, o un calculador de promedio de notas).
  3. Implementación de Lógica:
    • Declara las variables necesarias (usa const y let).
    • Crea mínimo bucle para interactuar con el usuario.
    • Usar un if/else para evaluar esos datos. Si la estructura es extensa debe mutar a switch.
  4. Salida de Resultados: Muestra por consola o mediante un alert toda comunicación necesaria para el flujo del script.
  5. Entrega: Sube tus archivos a un repositorio de GitHub y comparte la URL. Asegúrate de que el repositorio sea público para que pueda ser revisado.
